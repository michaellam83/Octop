# 第一阶段验证清单

## 1. 初始化验证

- [ ] 全新安装完成初始化后，存在“通联智多星”模型元数据。
- [ ] 模型 Base URL 为 `https://ai.allinpay.com/v1/`。
- [ ] 模型名称为 `auto`。
- [ ] 智多星不创建为普通 Provider；没有用户凭据时不会向员工流量提供共享 Key。
- [ ] 本地验证不要求 OA / 企业微信扫码登录。
- [ ] 存在“通联发仔”管理员模板。
- [ ] 模板默认使用用户级智多星直连模型。
- [ ] 普通用户看不到模板管理入口和模板详情。

## 2. 用户创建验证

- [ ] 管理员创建用户 `user_a`。
- [ ] 系统自动创建一个名称为“通联发仔”的 Agent。
- [ ] Agent ID 是 Octop 自动生成的合法短 ID。
- [ ] 重复执行用户创建或用户同步不会创建第二个托管 Agent。
- [ ] 删除并重新创建用户时，旧用户资源清理符合预期。

## 3. 用户凭据验证

- [ ] 管理员为 `user_a` 配置 ZDX Key A。
- [ ] 管理员为 `user_b` 配置 ZDX Key B。
- [ ] 管理员为 `user_a` 和 `user_b` 分别录入真实 OA username。
- [ ] 第一阶段用户的 Octop username 与真实 OA username 的映射方式已固定，并且唯一约束有效。
- [ ] 用户界面只显示“已配置”，不返回明文 Key。
- [ ] `ZDX_USERID` 等于管理员录入的真实 OA username。
- [ ] OA username 符合公司小写拼音和冲突追加数字规则。
- [ ] 修改用户 OA username 后，系统行为符合预期，不能继续使用错误身份。
- [ ] 没有 Key 的用户不会使用其他用户或管理员的 Key。
- [ ] Key 与 username 不匹配时调用失败，不会尝试其他 Key。

## 4. 智多星调用验证

- [ ] `user_a` 使用“通联发仔”完成知识库问答。
- [ ] `user_a` 使用“通联发仔”完成一条内部业务查询。
- [ ] `user_b` 同时调用，智多星侧身份和 API Key 不与 `user_a` 串用。
- [ ] 后端业务或系统调用的请求包含当前用户的 `chatBizOptions.userid`。
- [ ] 智多星侧可以依据 `userid` 校验用户权限和可读范围。
- [ ] 普通不涉及后端业务的对话请求，按智多星接口实际要求验证 userid 是否可选；无论是否可选，都不能使用其他用户的 userid。
- [ ] 用户自建专家选择“通联智多星”时，仍使用当前用户自己的 Key 和 username。
- [ ] 用户自建专家选择其他模型时，使用管理员配置的其他模型 Provider。
- [ ] “通联发仔”不能切换到其他模型。
- [ ] 业务查询超时、Key 无效和权限不足时，前端显示可理解的错误，不泄露凭据。

## 5. 托管 Agent 权限验证

- [ ] 用户看不到编辑按钮。
- [ ] 用户看不到删除按钮。
- [ ] 用户看不到工作区、Skill、插件、工具、MCP、人格和记忆管理入口。
- [ ] 用户可以打开对话。
- [ ] 用户可以停用 Agent。
- [ ] 用户可以重新启用 Agent。
- [ ] 直接调用 PATCH API 不能修改托管 Agent。
- [ ] 直接调用 DELETE API 不能删除托管 Agent。
- [ ] 直接调用模型切换、插件、Skill、工作区等 API 会被后端拒绝。
- [ ] 停用后会话和历史数据仍然保留。

## 6. 模板同步验证

- [ ] 管理员修改“通联发仔”系统提示词或预设文件。
- [ ] 模板版本号递增。
- [ ] 运行中的 `user_a` 和 `user_b` 实例获取新版本。
- [ ] 运行中的实例自动 reload 或在当前会话结束后 reload。
- [ ] 停用实例不会被错误启动，但下次启用时使用新版本。
- [ ] 用户自己的记忆、会话和个人文件未被覆盖。
- [ ] 同步失败时有管理员可查的审计记录。

## 7. 安全验证

- [ ] 普通用户 Provider 接口不返回 API Key。
- [ ] 管理员接口只返回脱敏 Key 或配置状态。
- [ ] 日志中 Authorization 已脱敏。
- [ ] 请求 dump 不包含明文 Key。
- [ ] 全局环境配置接口不暴露用户级 ZDX Key。
- [ ] 工作区文件搜索不到用户级 ZDX Key。
- [ ] 备份和恢复后凭据仍按预期可用或明确要求重新配置。

## 8. 回归验证

- [ ] 普通通用专家仍然可以创建、编辑和删除。
- [ ] 其他模型 Provider 行为不变。
- [ ] 原有管理员模型配置页面不被破坏。
- [ ] 原有 Skill、插件和 MCP 功能不受影响。
- [ ] SQLite 迁移通过。
- [ ] PostgreSQL 迁移通过。
- [ ] 单元测试通过。
- [ ] 集成测试通过。
- [ ] Dashboard 类型检查和构建通过。

## 9. 建议记录的验证信息

每次验证记录以下信息，便于定位身份串用和路由问题：

```text
测试用户：
OA username：
Octop Agent ID：
逻辑模型：
实际运行时 Provider：
智多星 userid：
Key 脱敏值：
请求时间：
请求类型：知识库 / 业务查询 / 普通对话
结果：
```

禁止记录完整 API Key、完整 Authorization Header 或包含敏感业务数据的原始请求体。
