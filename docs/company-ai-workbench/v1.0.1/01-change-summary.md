# 一期改造重点与 v1.0.1 范围

## 1. 基线和版本定义

- 基线是开源 Octop 的 1.0.1 代码线，当前仓库的 Python 包版本也已定义为 `1.0.1`。
- 本次一期改造没有另起一套应用，而是在 Octop 原有多用户、专家、Provider、Skill、Connector、知识库、通道和桌面端能力上增加公司工作台能力。
- v1.0.1 的产品名称为 AllinpayAI；“通联发仔”是一期的托管型专用专家。
- 一期封版的 Git tag 应在代码、测试和测试环境回归通过后再创建。当前工作区的未提交修改应先按发布流程审查，不能直接把整个工作目录作为发布包。

## 2. 管理员、用户和数据隔离

- 增加用户级智多星凭据配置：每个用户可以保存自己的智多星 `userid` 和 API Key。
- 凭据写入 Secrets/加密存储，普通用户不能读取其他用户的 key，日志和错误消息也不应回显完整凭据。
- 新建用户、邀请用户、SSO 用户首次进入和托管专家启动时，会按幂等规则创建或补齐该用户的“通联发仔”。重复执行不会重复创建专家或重复写入无效数据。
- 增加托管专家相关数据库迁移和元数据，用于区分托管类型、配置锁定状态和模板版本。
- 管理员可以在托管模板中维护提示词、欢迎语、快捷问题、任务示例以及纳入托管模板的内置技能/技能包，并发布到所有用户的“通联发仔”。
- 托管模板更新使用版本和重载机制，用户侧不直接修改专用模型、用户 key 和管理员控制的模板内容。

## 3. 智多星专用直链

- “通联发仔”的智多星调用不是普通 Provider，不进入普通 Provider/model 下拉列表，也不成为普通专家的默认模型。
- 托管配置只保存智多星服务的 Base URL、模型标识和调用方式；真正调用时使用当前登录用户自己的 `userid` 和 key。
- 智多星请求携带用户级 `userid` 等业务参数，不允许回退到管理员 key、其他用户 key 或公共 Provider key。
- Web、已接入的 IM/QQ 通道统一解析目标托管专家后进入直链服务；不把这条请求错误地重新送进普通 Harness Provider 链路。
- 普通专家仍使用 Octop 原有 Provider 选择、模型配置、Harness Agent 和工具编排；管理员新增的普通模型配置只影响普通专家。
- 对“最近几天、今天、当前”等相对日期，服务端先取得服务器当前日期，再把明确日期注入智多星查询，避免智多星内部固定知识日期造成误判。
- 对政策、竞品、公开产品资料、天气和明确要求“联网搜索”的问题，先经过管理员配置的公网搜索 Provider（一期使用 Tavily）获取公开资料，再将经过限制和脱敏的检索上下文交给智多星整理。
- 搜索结果被视为不可信外部上下文，不允许覆盖系统规则、用户隔离规则或泄露凭据。
- 统一处理流式错误、余额/额度不足、超时和配置缺失，避免前端在流式已经完成后又追加一个重复错误框；必要时保留可识别的错误码供日志排查。
- 对智多星返回内容中的 `<thinking>...</thinking>` 片段做用户侧过滤，避免把内部思维链直接展示给用户。
- 记录托管专家的输入、输出和 token 用量，使其可以纳入 Token 统计和管理员审计范围。

## 4. 托管专家的能力边界

“通联发仔”一期采用专用模型链路，故意不把普通 Octop 工具能力混入其中：

- 禁用 Harness Skill、Skill Package、Connector/MCP、浏览器、工作区文件、知识库工具、子智能体和普通模型切换。
- 禁用附件解析、通用快捷指令和专家互相调用，避免用户误以为托管专家支持普通专家的全部工具。
- 在“通联发仔”窗口隐藏快捷指令和专家选择；在其他普通专家窗口的专家选择器中也过滤掉“通联发仔”。
- 普通专家继续保留 Octop 的技能、技能包、连接器、知识库、附件和工具能力。
- 技能包在存储根目录不是 `/` 的情况下，普通用户不能直接从包目录挂载使用，但可以复制到自己的专家工作区；托管专家不参与这套普通工作区技能机制。

## 5. 前端和权限改造

- 普通用户保留对话、专家、Token 统计、个性化和已授权通道等业务功能；自动化入口一期对普通用户隐藏，后续交互优化后再开放。
- 管理员保留用户、模型、Provider、存储、插件、托管模板和高级配置管理能力。
- 普通用户不能管理托管模板、公共模型、用户凭据策略和全局搜索 Provider。
- “通联发仔”卡片和对话页隐藏不适用的编辑、删除、工作区、工具选择等操作。
- 隐藏一期暂不开放的帮助与反馈、项目地址等菜单；默认界面配色调整为“科技”。
- 完成 AllinpayAI 品牌、应用名称、Logo、通联发仔头像和桌面端 loading 吉祥物替换，桌面打包产物使用 AllinpayAI 名称。

## 6. 兼容性和验证重点

- 普通 Provider 的注册、启停、模型列表和普通专家启动逻辑保持原有语义。
- 专用智多星配置不作为普通 Provider 的共享凭据，避免“管理员新增一个智多星配置后所有专家都误走同一用户 key”。
- 修复模型配置弹窗无法正确读取自定义模型、专家启动状态与实际可对话状态不一致等一期验证问题。
- 增加托管专家、用户级凭据、直链调用、公网搜索、时间注入、权限边界和流式错误的后端测试。
- 数据库迁移保持 SQLite/PostgreSQL 结构一致，并在全新数据库和已有验证数据库上分别验证。
- 前端改动必须从 `dashboard/` 构建到发布产物，不能直接编辑 `src/octop/dashboard/`。

## 7. 一期明确不包含的内容

- 不把智多星用户级 key 改造成共享 Provider。
- 不让“通联发仔”直接复用普通专家的 Skill、MCP、Connector、知识库和工作区工具。
- 不开放普通用户修改通联发仔的专用模型、用户 key 和托管模板。
- 不在一期引入高可用集群、生产级多实例调度、完整企业 SSO 自动发放智多星凭据等能力。
- 不以旧版验证数据库或旧用户数据作为正式发布依赖；测试环境应使用隔离的数据目录重新初始化。
